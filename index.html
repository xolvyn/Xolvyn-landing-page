How is Xolvyn different from free open-source codebase analyzers?

Free graph and visualization tools draw you a dependency map and stop there — they don't find vulnerabilities, don't scan for CVEs, don't rank findings by blast radius, don't open fix PRs, and don't produce an executive-friendly letter grade. Xolvyn fuses that architectural awareness with active security scanning, so the map isn't just something to look at — it's what tells you which vulnerability actually matters. That combination is something pure visualization tools cannot do.

Why not just use Snyk or Semgrep plus a separate graph tool?

Running them side by side misses the point: a vulnerability's real risk depends on what depends on it. A medium-severity finding on a load-bearing file that 47 modules import is far more urgent than a critical finding on an isolated leaf node nothing touches — but two disconnected tools can't tell you that. Only fusing the security scan with the dependency graph turns a pile of findings into actionable prioritization.

Does Xolvyn store or train AI on my source code?

No, never. Xolvyn performs a shallow git clone with depth=1 into an isolated temporary directory, runs the entire analysis in memory, and immediately deletes the clone. We store only computed metadata — architecture maps, complexity scores, and security findings — never your source code itself. Your code is never used to train any AI model, ours or third-party. Your intellectual property stays yours.

How is the @mentor AI different from ChatGPT or GitHub Copilot?

@mentor is grounded in your repo's actual dependency graph — it answers with real file paths and import chains instead of hallucinated guesses.

Which programming languages and frameworks does Xolvyn support?

Xolvyn currently supports TypeScript, JavaScript (both ESM and CommonJS), Python, Go, and Java with full AST-level dependency mapping. The security audit engine works on every text-based source file regardless of language. Monorepo tooling — including Turborepo, Nx, Lerna, and Yarn Workspaces — is supported natively.

How does the AI Auto-Fix Engine create Pull Requests?

When a security finding is marked auto-fixable, clicking "Apply Fix" triggers the Xolvyn Auto-Fix Engine. It reads the vulnerable code snippet, generates a safe replacement using AST-aware remediation logic, commits the fix to a new branch on your repository, and opens a Pull Request automatically through the GitHub or GitLab App. For dependency CVEs, it bumps the version in your package.json, requirements.txt, or go.mod and opens the PR. Every fix includes a confidence score, and nothing merges without your explicit review and approval.
